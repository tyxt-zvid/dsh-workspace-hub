# 04 · 独立设计评审：工作区中枢 Console 重构

> 评审对象：`docs/redesign/03-strategy.md`、`prototype/index.html`、`docs/redesign/README.md`
> 评审标准：`02-opendesign-toolkit.md` §4（44 条 = 24 P0 + 20 P1）；对照 `01-current-audit.md` 的实测结论
> 方法：逐条静态判定 + 自截 12 路由（1440×900、亮/暗、820px 窄面板）+ Playwright 1.64.1/Chrome-for-Testing 1228 实测键盘与焦点（42 项断言）
> 证据记法：`route / selector / index.html:行号`；截图均为本人自截，不引用 `screens/` 既有图

---

## 1. 裁决

**ship with fixes**——方向可进入实现，但**不得**作为「P0 全过」的验收基线。

IA、对象模型、视觉方向和状态设计都成立，且不是纸上方案：概览一屏真的能回答「在跑什么/卡在哪」；密度、发丝线、单一实心的视觉纪律在 12 个路由上都守住了；键盘主路径大部分可闭环。但按团队自己写下的合并门槛（02 §4 P0 全过），24 条 P0 有 **4 条未过**、20 条 P1 有 **6 条未做**，另有 3 个键盘契约硬伤（派发 sheet 的 Enter 会劫持「取消」、快速捕获 Tab 陷阱、浮层关闭后焦点归位到错误的控件）。这些都不是架构级返工，属于 1–2 天可修的原型/规范修订；修完、把 Host 依赖项从验收里剥出去，再冻结 baseline。不是 ship：对比度问题在亮色主题下是全局性的；不是 not ready：策略与原型的主体质量高于常见 redesign 提案。

## 2. P0 未过项（4/24）

### #4 对比度（P0）— **FAIL，仅亮色主题**
| 用法 | 证据 | 实测 |
|---|---|---|
| 正文/元数据 `--fg-3:#81858c` | `.hint`（index.html:118）、`.row-sub`（230）、`.page-sub`（549）、`.set-hd h2`（553）、`.skill-desc`（581）、`.env-error`（786） | on `#fff` **3.71:1**；on `#f9fafb` **3.55:1**（<4.5） |
| 琥珀色当文字 `#f59e0b` | `.pri.high`（295）「高」、环境失败态 `.server-state`（1281）「启动超时」 | on `#fff` **2.15:1** |
| 绿色图标 `#22c55e` | `.save-state .ic`（420）、`.editor-conflict` 对勾 | on `#fff` **2.28:1**（非文本 UI 需 3:1） |
| 输入/控件边界 `--border-strong:#0000001a` | `.input`（356）、`.capture`（369）、`.group` 的 `--border` | on `#fff` **1.26 / 1.09:1** |

暗色全部达标（`#adb2b8 on #151517` = 8.54，amber 8.49，green 8.00，所有状态字 ≥7.36）。亮色 token 与宿主值一致（审计 §8.1 明确 `label-tertiary` 亮色就是 `#81858c`），所以这同时是**宿主 token 的问题**，评审不能静默放行。
**修法**：亮色建立独立语义文字阶——正文/元数据改用 `#61666b`（5.80）或把 tertiary 压到 ≥4.5；琥珀文字改 `#b45309`（约 4.8）、绿色图标改 `#15803d`；输入边界用宿主 `border-l4`。若必须严格等值宿主 token，把该条标为「宿主 pending + 亮色豁免」，并在 02 §4 写明豁免理由。

### #16 五态覆盖（P0）— **FAIL（仅在「任务」表面成立）**
`#/states` 的 8 个块（空/骨架/错误/冲突/离线/权限/长内容/200 行）都只描述任务列表；**对话、环境、设置三个取数表面没有 loading/error/离线设计**，断网和权限态也只停在画廊里，不落在真实表面。README §4「全部有设计」+ §6.6「每个取数表面五态齐备」属 overclaim。
**修法**：给 `#/states` 补「对话 · 骨架/错误」「环境 · 探测中/不可达」「设置 · 读取失败」三组；或修订 02 §4 的判定范围（原型只验任务表面，其余转实现验收），并在 README 改口径。

### #27 目标尺寸 ≥24×24（P0）— **FAIL**
实测：`.status` **22×22**（266）、`.row-sel`/复选框 **14×14**（256/300）、主题分段按钮 **22×18**（163）、`显示已关闭` 开关 **26×14**（793）、`.badge` 高 18。行内 24 高的 `.mini`/`.icon-btn` 达标。
**修法**：状态控件 ≥24（建议 28）；复选框用 label 做 24×24 命中区；主题按钮 24×24；开关 26×18 或 label 撑高。把「所有可点元素 min(w,h)≥24（行内按钮 ≥24 高 + 8px 间距例外）」写成 Playwright 断言。

### #32 状态不能只靠颜色（P0）— **FAIL（子会话行）**
`subRowHTML` 的圆点 `doing/warn/idle`（1578）没有任何状态文案；`sessions` 里「路径展示评审」是 **amber 点 = idle+未读**，而 amber 在任务/环境里表示 blocked/warn，同一颜色两种语义。`.dot.doing` 与 `.dot.done` 还同为绿色（277/279），看板「进行中/已完成」两列同色。
**修法**：给子会话行补「运行中/空闲/已关闭」文字或差异形状；idle 改中性空心、unread 只靠徽标；全局统一 running/done/idle/warn/error 的形状+颜色映射（见 §7 建议 4）。

## 3. P1 问题清单（按影响排序）

1. **派发 sheet 的 Enter 会劫持「取消」按钮**：`document` 级 keydown 对所有非 textarea 的 Enter 直接 `sheetSend()`（index.html:2464）。实测 Tab 到「取消」按 Enter → 出现「已派发给…」并写入运行条，而不是取消。**修法**：仅在焦点不属于交互控件（button/select/input）时才提交，或只认 `[data-act="sheet-send"]` 的激活。
2. **快速捕获 Tab 陷阱**：输入框里每次 Tab 都 `preventDefault` 并重开详情（2390-2392）。实测 Tab×3 焦点始终在 `#capture`，优先级/归属两个 select 键盘不可达。**修法**：仅详情未展开时首次 Tab 展开，之后 Tab 正常进入详情控件。
3. **浮层关闭后焦点归位错误**：`restoreFocus()` 保存的是旧 DOM 节点，`render()` 后 isConnected=false，回退到 `[data-act="palette-open"]`（1910-1916、2125）。实测 Esc 关闭派发后焦点落在头部「⌘K」按钮，不是触发行。**修法**：保存 `{route,rowId}` 并在渲染后按选择器重新取；删除 ⌘K 兜底。
4. **<900px 丢失工作区身份、同步状态、执行者/时间/优先级**：`sync`/`hd-path`/`ws-switch`/`row-meta` 全部 `display:none`（873-885）。820px 实测头部只剩「工作区中枢」，没有工作区名/路径/同步（也无法手动刷新），任务行只剩状态+标题，直接违反 G3「任务行始终显示执行者与最近活动」。**修法**：同步态折叠成图标+tooltip；工作区名保留短名；执行者/优先级移进第二行而非删除。
5. **看板假 affordance**：板头写着「拖动排序 · 键盘 [ ] 改状态」（1501），但没有 drag handler，也 grep 不到 `[`/`]` 键盘分支；实测按 `[` `]` 无任何变化。**修法**：实现拖拽与 `[`/`]`，或删掉这句、改为卡片菜单改状态。
6. **任务搜索不存在**：策略 §5.5 要求任务搜索，`/` 在任务页却聚焦捕获框（`focusSearch`），DOM 里没有任务搜索 input（实测 hasSearch=false）。**修法**：加任务搜索框（客户端过滤 ≤200）+ `/` 聚焦它；配合 §4.2 的 spec 修订。
7. **状态色映射三套并存**：任务行 doing=蓝环（272）、看板 doing=绿点（277）、done=绿点（279）、子会话 idle=amber（1578）。**修法**：一张状态语义表贯穿列表/看板/会话/环境，颜色只做辅助。
8. **对话页两个实心主按钮**：`新建子会话`（1548）与行内 `发送`（1587）同为 `.btn.primary`，违反 §7「唯一实心按钮」；实测同屏 2 个。**修法**：`发送` 降为 secondary 24px，或把新建收进工具行 ghost。
9. **空态演示与计数矛盾**：`applyDemo("empty")` 只替换列表，状态条/导航/筛选仍是 12/5/3；自截 `#/tasks ⋯>空状态` 显示「还没有任务」同时「全部 12 · 待办 5」。**修法**：空工作区用零数据快照；筛选空态用 `emptyFilterHTML` 区分。
10. **主操作是死胡同**：概览「查看日志」、运行行「打开」、子会话「打开」、环境 URL 都只弹 toast（2307/2316/2069/2310）。其中「查看日志」正是 §5.4 承诺的日志浮层入口。**修法**：打开会话 → `#/sessions` 并展开目标；日志 → popover/浮层；至少不要给不可用的主动作。
11. **命令面板语义缺失**：`role=dialog` 有（1746），但结果是 `div.pal-row`（无 role/aria-selected），无 listbox/`aria-activedescendant`，Esc 后焦点回 `BODY`。**修法**：listbox/option + activedescendant；关闭后回触发按钮。
12. **toast 嵌套 live region**：容器 `aria-live="polite"`（925）+ 每个 toast `role=status/alert`（1799），部分读屏会双播。**修法**：只保留容器 aria-live，或只保留 per-toast role。
13. **10.5px 键帽越档**：`.kbd{font:10.5px/1 …}`（124）；渲染字号实测含 10.5px，正是审计 P2-1 批评的「半像素字号」。**修法**：改 11px，纳入 §5.1 六档。
14. **真实任务行没有 title 兜底**：`taskRow` 的 `.row-title`（1347）无 `title` 属性（实测 false），长标题在 44px 行只能硬截断；只有 `#/states` 演示块加了 title。**修法**：`title=标题`，展开态全文可读。
15. **环境失败只显示 1 行**：`envRow` 只渲染 `s.error[0]`（1281），策略 §5.9 要求尾 3 行 + 查看日志浮层；「查看日志」是 toast（2310）。**修法**：保留 3 行 mono 尾 + 日志浮层。
16. **会话列表不按注意力排序**：`SESSION_SEED` 里 s1(3m)、s2(昨天 19:41 空闲)、s3(12m **未读 2**)、s4(closed)；运行中且有未读的「中枢重构」排在两个空闲会话之后。**修法**：未读/running 优先，再按最近活动。
17. **设置页默认就演「冲突 + 未保存」**：`editor-conflict` 与 dirty 初始即渲染（1649-1652），首次进入像故障；`ctx-save` 初始永远「保存中…」（1631）不会落定。**修法**：初始「已保存」，冲突移入演示态或 ⋯ 菜单。

> 其余 checklist P1 未过（与上面部分重叠）：#13 计数/端口未用 mono（只有 tabular-nums）；#21 无 2/4/8s 退避与可复制错误 ID；#22 长标题无 title；#29 焦点归位（见 3）；#31 `/` 与 `[ ]` 名不副实、`↑↓` 未实现。#15/#23 为软问题。

## 4. 与策略的偏差

### 4.1 原型没做到（实现前必须补或明确降级）
- **搜索**：任务页无搜索框，`/` 聚焦捕获（§5.5、§6.4）。
- **行焦点**：只有 `j/k`，没有 `↑/↓`（§6.4）；行是 `div[tabindex=0]` 无 role，任务页实测 89 个 tab stop（含整行隐藏操作）。
- **看板**：无拖拽、无 `[`/`]`、无卡片改状态入口（§5.5 只承诺了两次）。
- **分组/编辑**：默认分组是状态，不是 §5.5 的「需要我处理/进行中/最近完成」；「分组」控件是 toast 占位；详情与优先级不可编辑，备注不可追加（只标题可编辑）。
- **派发**：无 submitting loading、无「派发后打开该会话」行为、无 409 就地冲突（§5.6）。
- **环境**：6 个互斥状态只实现 4 个（缺 external、stopped 与 timeout 之外的分化）；失败尾 1 行；无日志浮层（§5.9）。
- **设置**：冲突只给 2 个出口（缺「另存」）、无离开未保存拦截、技能新建只有 toast（§5.8）。
- **选中态**：§5.1 写「business 蓝左 2px + 4% 底」，原型 `.row.sel` 只有 14% 白底、没有左色条（222）。
- **概览**：「查看全部」跳到 `filter=all`，不是 §3 的「按注意力筛选」（1231）。
- **失败路径**：全部写操作只有成功分支；乐观更新/回滚/409/离线重试均未演示（§6.2）。
- **五态/加载阈值**：见 P0 #16；0–300ms/2–10s/15s 三档未体现（§6.6）。
- **设置/日志/命令面板**之外的次级屏：无工作区切换器、无 returnPath 恢复（§6.5，原型范围外但验收清单要写明）。

### 4.2 策略本身要改（spec corrections，建议直接采纳）
1. **§5.3 与 §5.1 字号打架**：行标题一处 13/500、一处 14 行标题。统一 14（原型即 14），并删除半像素 10.5。
2. **§5.5 默认分组与 §3 概览重复**：「需要我处理/进行中/最近完成」和概览注意力队列是同一信息，且与状态 chips/状态条冲突。建议：任务页默认**状态分组**，把注意力做成顶部 pinned「需要我处理」筛选；或概览只保留，不在任务页再分组。
3. **搜索能力与 Host 不匹配**：§5.5「搜索与筛选走服务端查询」，但审计里 `tasks.list` 只有 status/mine，没有 search 参数（§9.4/§11 也未列）。改为「≤200 客户端过滤，超阈值再提 Host 参数」，并写入 §9 依赖表。
4. **设置 CAS 冲突不可实现**：§5.8 的三选一依赖文件 hash/If-Match，而 §9 自己把「文件保存冲突检测」列为 Host 改动。Host 未就绪前，设置冲突不应作为 P0/P1 验收，原型默认展示冲突会误导评审。
5. **选中语义两套**：导航下划线用 `brand-primary`（暗色即白），选中行却要求 business 蓝（§5.1 注解）。二选一：全局用 business 蓝做「选中/焦点」，或以「白底/黑底 + 细条」做选中，不要混用。
6. **色彩预算两份文档冲突**：§7「单屏彩色面积 <5%」 vs 02 §4 #3「强调 5–10%」。控制台场景应取 <5%，并把 #3 的判定改为「只设上限」。
7. **焦点环实现口径**：§5.1「outline 2px + 2px offset」，行内容器用 inset 2px（93/529）——需补一句「行内容器允许 inset 2px 环」，否则实现会按字面漏掉行焦点。
8. **截图清单过期**：§8 的 `02-work-dark`/`03-work-expanded-dark` 与实际 `02-tasks-dark`/`03-tasks-expanded-dark` 不符，且 12 张只列了 10 张；README §8 的 screens 数量也要同步。
9. **入口/胶囊/returnPath 不可原型验收**：§6.5 的宿主入口、状态胶囊、returnPath 不在原型范围；§12 验收表应明确标「实现阶段人工验收」，不能拿原型截图当证据。
10. **状态色表缺失**：文档只定义 6 种环境状态，没有定义 running/done/idle/warn 在各组件中的形状+颜色+文案；这是 §3 对象模型应有的内容（本次 #32/P1-7 的根因）。

### 4.3 提案集合体核验（README before/after 声明）
- **有据**：85.5 请求/分、55 个 button、5 个零 UI 入口、7 次点击看清现状、8 次点击派发、服务器 20–30s 阻塞——均能在审计 §10/§3.2/§11.2 找到对应证据（审计 §10a/10b/10e）。
- **部分成立**：「新建并派发 3 步」只在「任务已存在」时成立（聚焦行 `d` → 选目标 → Enter）。快速捕获只创建、不派发，实测从 `n` 到派发完成至少是 n→输入→Enter→Esc→j→d→Enter，**没有兑现审计 (b) 的理想「标题+目标会话一次提交」**；这是 before/after 表里最需要降调的声明。
- **Overclaim**（应改写）：①「44 条 P0 全过」的隐含前提（实际 4 条未过）；②「点击区 ≥24px」（22/14/18）；③「浮层关闭后焦点归位」（回落到 ⌘K）；④「每个取数表面五态齐备」（只有任务）；⑤「唯一实心按钮」（对话页 2 个）；⑥「失败给日志」（只有 toast）；⑦「键盘闭环」（Tab 陷阱 + Enter 劫持）。
- **未证**：一次快照、退避、乐观回滚、CAS、软删除 Host 端点——原型无网络、无失败路径，是契约不是证据，README 应把 §6 标为「待实现契约」而非现状。

## 5. 亮点（≤6）

1. **概览真的回答了 G1**：`#/now` 一屏 = 5 条可解释注意力（每条带原因第二行+一个主操作）+ 3 条运行（执行者/已运行/最近活动）+ 3 台环境（starting 与 failed 互斥呈现，EADDRINUSE 写到行内）；不是「数据都有」而是「该看什么都有」。
2. **视觉纪律是真的**：6 档基础字号（11/12/13/14/15/20，仅键帽 10.5 越档）、圆角只用 4/8/12/16、0 emoji（Extended_Pictographic=0）、0 渐变、0 indigo、1 条宿主缓动、发丝线列表；暗色对比度 7.36–10.42。这套静态项在 44 条里过了 20 条 P0 的绝大部分。
3. **关键键盘路径实测可用**：`n` → 输入 → Enter 创建且焦点不丢、计数 12→13、行插到分组顶；`j` 聚焦后行尾操作 opacity=1；`x` 完成 + `status` toast + 撤销恢复；`⌘K` 过滤「设置」只剩 1 行、Esc 关闭；sheet 内 1/2/3 与 Tab 陷阱正常。
4. **焦点与 reduced-motion 做对了**：两主题都是 2px 环（暗 `#7aaaff`、亮 `#4176e6`，亮色对白 4.23:1 >3）；`prefers-reduced-motion` 下 animation/transition 实测为 0s，脉冲点静止。
5. **状态画廊是可直接复用的验收素材**：错误态回答「发生了什么/影响/下一步」，冲突有两个出口，离线/权限/长路径/200 行都有；比多数原型的「一个 Error 文案」高一个量级。
6. **密度是宿主原生而非截图拼贴**：44/56px 行、分组头 11/600/0.04em、tabular 数字、mono 路径、零卡片噪声；亮色不是反色（近黑主按钮、语义色加深），`#/now-light` 与 `#/settings` 两屏可信。

## 6. 键盘 / 可访问性实测

## 7. 对最终落地的 5 条最高价值建议

1. **先冻结 Host 依赖矩阵，再排 P0/P1**：`hub.snapshot`、`tasks.list.search`、文件 hash/If-Match、服务器 job+logs、软删除端点五项决定设置冲突、任务搜索、日志浮层能否存在。凡 Host 未就绪的界面，验收改为「前端降级 + 明确说明」，不要留成可点但只弹 toast 的入口。
2. **把键盘分发重写成一套**：全局 keydown 先判断 `e.target` 是否交互控件（button/select/input/a）；Enter 只在非控件或 sheet 主按钮上提交；焦点归位用稳定选择器（`data-act` + row id）而非 DOM 引用；补 `↑↓` 与 roving tabindex；删掉没有实现的 `[ ]` 提示。
3. **建立亮色语义阶 + CI 门禁**：亮色文字/图标/边框独立成一套（≥4.5/≥3），用 Playwright+axe 跑对比度、24px 命中、五态；再加 token lint（禁 hex 直写、禁非档位半径、禁 10.5px、禁 emoji/渐变）。这套门禁一次投入，后续每个 PR 都复利。
4. **一张状态语义表贯穿所有组件**：running=蓝环、done=绿勾、idle=空心、blocked=琥珀感叹、failed=红点+错误行；形状优先、颜色辅助、文案兜底。所有视图（任务/看板/会话/子会话/环境）只能引用这张表，禁止在局部 CSS 里另起映射。
5. **把「失败路径 + 窄面板」列为 P1 阶段的一等验收**：四个可录制的坏路径（离线、409、写失败回滚、服务启动失败）+ 820px 下必须保留工作区身份/同步态/执行者；并给会话列表加注意力优先排序。否则「乐观更新/不跳变」只停留在文案，窄面板会先丢掉 G3。
